# Requirements traceability: SIH 2026 problem statement 26067 (INCOIS)

One row per requirement of the problem statement. Each row gives what OceanLens 3D does, where it is implemented and
which test proves it. The status is one of **Met**, **Partly met** (what is missing is written down) or **Not met**.

- File paths are relative to the repository root.
- Browser tests run headless against the built single file: `python tools/run.py --suite <name>`.
- `python tools/check.py` runs everything: hygiene, the build check, a fresh build and every suite.
- "By real clicks" means the test moves the mouse and clicks the control on screen, as a user would. Other tests set
  values through the app's own actions.
- Rows 2b, 3c, 3d, 5a, 5f, 6a, 6b, 7d, 9a–9d, 10a and 10b were updated on 4–8 November 2026 for the third model
  (IGORA), the forecast case, the moorings, the satellite products and server models. On 9 November 2026 an audit
  checked every row and every cited test against the code. The latest full test run is given in "How to re-run the
  evidence" at the end.

## Read this first

- **Plain JavaScript, not a framework.** The app is classic browser scripts (no React, no npm, no bundler), with
  Three.js r128 (WebGL) as its only library, inlined. `python build.py` makes one self-contained HTML file. It opens by
  double-click with no network, which is what lets it run from a USB drive or an air-gapped INCOIS machine. The
  plugin API (`window.OceanLens`) provides the modularity a framework would otherwise give. The problem statement
  asks for "modern JavaScript frameworks", so row 5e is marked Not met.
- **Our own NetCDF readers, with xarray as an option.** Python reads and writes NetCDF-3 with `ncio.py` and reads
  NetCDF-4/HDF5 with `nc4.py` (numpy and zlib only); the browser has its own NetCDF-3 and NetCDF-4 readers. Where
  xarray is installed, `--engine xarray` reads model files through it instead (row 3d). The
  NetCDF-4 readers were checked on real files against independent sources: a Copernicus GLORYS native file against
  the Copernicus Zarr store, and two Argo S-files against Ifremer ERDDAP (rows 3a and 3d).
- **One past case, from three models.** The models are the HYCOM GOFS 3.1 analysis and the Copernicus Marine GLORYS12V1
  reanalysis (`GLOBAL_MULTIYEAR_PHY_001_030`, row 10a), switched in the app; a third, INCOIS's IGORA reanalysis, comes from the INCOIS LAS (row 10b).
  The data are cyclone Amphan: 8 analyses 3 days apart (4–25 May 2020; for GLORYS the daily means centred on the
  same times), 11 levels from 0 to 1000 m, a 0.5° grid over 6–22° N, 61–92° E. That box leaves out the Andaman &
  Nicobar Islands. The pipeline hard-codes this domain, the 11 depths, the 4 model variables and the 8 times. It is
  a historical hindcast. A second case, the latest Copernicus Marine forecast (`build_forecast.py`, run daily; the
  server's `--reload` picks it up), can be served on the same map (row 9a).
- **The 3D view draws the snapshots in the page, and server models on the same case.** A NetCDF model file given to
  the server that covers the map and has a time within 12 h of each of the 8 analyses is put on the app grid by the
  server (`/api/v1/datasets/<id>/model`) and joins the Model switch, streamed when chosen. Other files are served
  through WMS, WCS, OPeNDAP and REST only (rows 5f and 6b).
- **Gliders.** The OceanGliders GDAC has no glider inside the map for May 2020, so the main real-data scene has no
  glider. Two real 2016 glider files (the BoBBLE experiment) are in `samples/`; they import as dives and climbs and
  show with "Show all times". The gliders in Synthetic mode are synthetic and labelled as such (row 2c).

## How to re-run the evidence

```
python tools/check.py                                    # everything: hygiene, build check, fresh build, every suite
python tools/run.py --list                               # the suites and their tests
python build.py --out dist/test.html                     # a build to test against
python tools/run.py --build dist/test.html --suite smoke     # real clicks: depth slider, iso value, BGC tabs, colour key
python tools/run.py --build dist/test.html --suite extend    # plugins, every sample file, real file layouts, controls, server mode
python tools/run.py --build dist/test.html --suite render    # colours against the bar, the 3D look (Look3D)
python tools/run.py --suite server                       # REST, WMS, WCS, OPeNDAP (no browser)
python -m unittest discover -s data-pipeline -p "test_*.py"   # pipeline, NetCDF-3 and NetCDF-4, Argo and BGC selection
python data-pipeline/build_snapshot.py --model glorys --temperature-only --check   # GLORYS rebuilt from the cache, byte for byte
```
