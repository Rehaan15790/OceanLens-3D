# Requirements traceability: SIH 2026 problem statement 26067 (INCOIS)

One row per requirement of the problem statement. Each row gives what OceanLens 3D does, where it is implemented and
which test proves it. The status is one of **Met**, **Partly met** (what is missing is written down) or **Not met**.

- File paths are relative to the repository root.
- Browser tests run headless against the built single file: `python tools/run.py --suite <name>`.
- `python tools/check.py` runs everything: hygiene, the build check, a fresh build and every suite.
- "By real clicks" means the test moves the mouse and clicks the control on screen, as a user would. Other tests set
  values through the app's own actions.
- Last checked against the code and the tests on 6 October 2026: of 193 tests (every suite but `fingerprint`), 189
  passed, 1 failed and 3 were skipped (see "How to re-run the evidence" at the end).

## Read this first

- **Plain JavaScript, not a framework.** The app is classic browser scripts (no React, no npm, no bundler), with
  Three.js r128 (WebGL) as its only library, inlined. `python build.py` makes one self-contained HTML file. It opens by
  double-click with no network, which is what lets it run from a USB drive or an air-gapped INCOIS machine. The
  plugin API (`window.OceanLens`) provides the modularity a framework would otherwise give. The problem statement
  asks for "modern JavaScript frameworks", so row 5e is marked Not met.
- **Our own NetCDF readers, not PyNIO or xarray.** Python reads and writes NetCDF-3 with `ncio.py` (numpy only); the
  browser has its own NetCDF-3 reader. Neither reads NetCDF-4/HDF5 (rows 3a and 3d).
- **One past case, from one model.** The model is the HYCOM GOFS 3.1 analysis, not Copernicus GLORYS or the INCOIS
  LAS (rows 10a and 10b). The data are cyclone Amphan: 8 analyses 3 days apart (4–25 May 2020), 11 levels from 0 to
  1000 m, a 0.5° grid over 6–22° N, 61–92° E. That box leaves out the Andaman & Nicobar Islands. The pipeline
  hard-codes this domain, the 11 depths and the 4 model variables; the 8 times are fixed for HYCOM. It is a
  historical hindcast: there are no forecasts and no live or scheduled data.
- **The 3D view draws only the model snapshot embedded in the page.** It never streams model fields from the
  server. Model files given to the server are served through WMS, WCS, OPeNDAP and REST only (rows 5f and 6b).
- **Gliders.** The OceanGliders GDAC has no glider inside the map for May 2020, so the main real-data scene has no
  glider. Two real 2016 glider files (the BoBBLE experiment) are in `samples/`; they import as dives and climbs and
  show with "Show all times". The gliders in Synthetic mode are synthetic and labelled as such (row 2c).

## How to re-run the evidence

```
python tools/check.py                                    # everything: hygiene, build check, fresh build, every suite
python tools/run.py --list                               # the suites and their tests
python build.py --out dist/test.html                     # a build to test against
python tools/run.py --build dist/test.html --suite smoke     # real clicks: depth slider, iso value, BGC tabs, colour key
python tools/run.py --build dist/test.html --suite extend    # plugins, every sample file, real file layouts, controls, server mode
python tools/run.py --build dist/test.html --suite render    # colours against the bar, the 3D look (Look3D)
python tools/run.py --suite server                       # REST, WMS, WCS, OPeNDAP (no browser)
python -m unittest discover -s data-pipeline -p "test_*.py"   # pipeline, NetCDF, Argo and BGC selection
```

- The browser is `$OCEANLENS_BROWSER` (or `$CHROME`), else Edge or Chrome in their usual places (`docs/TESTING.md`).
- The run on 6 October 2026 (all suites but `fingerprint`, headless Chromium with software rendering): 193 tests,
  189 passed, 1 failed, 3 skipped. The failure is `perf`'s 2.5 s load budget at 4× CPU throttling (5.3 s). Two
  pipeline tests skip because the raw data cache is not in the repository; one splash test skips when the loading
  state is too short to observe.
- The netCDF-C check in row 5c was done by hand: start `python server/serve.py`, then open
  `http://127.0.0.1:8080/opendap/amphan-2020` with netCDF4-python (or any netCDF-C client) and read a slice. It is not
  part of the automated suite, because netCDF-C is not a project dependency.
